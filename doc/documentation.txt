PROFIT PILOT — DEVELOPMENT NOTES
From restarting the project to Version 1.0


1. Picking up the project again
------------------------------
- Returned to the original Java/React project after a long break.
- Reviewed the existing code, database, charts, and unfinished features.
- Defined V1: daily stock prices, indicators, news, and analysis export.
- Left prediction models out of scope.

2. Fixing imports and cleaning old data
--------------------------------------
- Made external API requests explicitly configurable.
- Added request spacing and tracking of failed and successful imports.
- Saved prices transactionally and prevented duplicate symbol/date rows.
- Refreshed the initial five stocks; retried GOOGL after a rate-limit issue.
- Backed up the database before removing obsolete prices and indicators.
- Kept recent data instead of backfilling the entire project break.

3. Indicators and export
------------------------
- Corrected and tested SMA, EMA, RSI, and MACD calculations.
- Added MACD signal and histogram series; separated RSI and MACD charts.
- Sorted chart data by date and improved indicator request handling.
- Calculated market movers from stored prices to save API requests.
- Updated ARFF export to calculate indicators from stored closing prices.
- Added browser downloads and fixed accidentally nested source folders.

4. Frontend redesign
--------------------
- Reworked the layout, navigation, charts, controls, and mobile styling.
- Improved market-mover cards and company-news presentation.
- Added loading, error, empty-result, and retry states.
- Displayed stored price dates, data freshness, and API budget information.
- Kept reloading stored data separate from requesting new provider data.
- Added Profit Pilot branding, favicon, and author link.

5. Budgets, scheduling, and stock coverage
----------------------------------------
- Added a shared PostgreSQL-backed rolling-24-hour request budget.
- Worked within the available 25-request price-provider allowance.
- Fixed a missing budget table during the first live verification.
- Verified the import flow with a controlled IBM request.
- Added startup checks, scheduled refreshes, cooldowns, and bounded retries.
- Used a US trading calendar and New York time for freshness checks.
- Added separate caching and budget handling for Marketaux news.
- Centralized the stock catalog and expanded it to ten companies:
  IBM, AAPL, GOOGL, MSFT, AMZN, NVDA, JPM, JNJ, KO, XOM.

6. Raspberry Pi deployment
--------------------------
- Set up Java 21, PostgreSQL, and Profit Pilot on the Pi.
- Transferred the database and checked the imported data.
- Packaged the built frontend inside the Spring Boot JAR.
- Configured automatic startup through systemd.
- Verified the website and API on port 18080 in the local network.
- The development computer was no longer needed to keep the app running.

7. Monitoring and updates
------------------------
- Added build revision, startup time, and import-status endpoints.
- Stored the last completed import result across restarts.
- Added dashboard visibility for build and import information.
- Created build, installation, and Pi status-check scripts.
- Included checksums, a previous-JAR backup, and rollback handling.
- Installed updates while preserving the existing Pi database.
- Checked logs and import results after roughly a day of operation.
